# 提交约定

本仓库**只保留一条提交**。

每次改动都并入那条提交、再覆盖远端历史，所以 `git log` 永远只有一行。这样做是为了让仓库页面干净——不展示开发过程中的调试提交。

## 一键提交

```powershell
# 把当前改动并入唯一提交，并推送到远端
.\scripts\push-latest.ps1

# 换掉提交信息
.\scripts\push-latest.ps1 -Message "DSH 启动器 v1.0.1"

# 同时把 tag 移到新提交（会触发 CI 重建对应 Release）
.\scripts\push-latest.ps1 -Tag v1.0.1

# 只看会做什么，不真推
.\scripts\push-latest.ps1 -WhatIf
```

等价的手工命令：

```bash
git add -A
git commit --amend --no-edit      # 或 --amend -m "新说明"
git push --force-with-lease origin main
```

## 注意事项

| 事项 | 说明 |
|---|---|
| **会重写历史** | 用了 `--force-with-lease`，若远端在你之后有别人的提交，推送会被拒绝而不是覆盖 |
| **旧提交不可恢复** | 被 amend 掉的提交对象如果没有 tag 或分支引用，会被 git 逐渐回收 |
| **需要强推权限** | 仓库需允许 force push（当前仓库是单人维护，没问题） |
| **tag 与 Release** | tag 默认不跟着动，仍指向发版时的快照；需要更新时加 `-Tag` 参数 |
| **协作者** | 其他人如果已经克隆过，需要 `git fetch && git reset --hard origin/main` 才能同步 |

## 版本发布

打 tag 会触发 GitHub Actions 自动编译并把 exe 附到 Release：

```bash
git tag -a v1.0.1 -m "v1.0.1"
git push origin v1.0.1
```

或用脚本一步完成：

```powershell
.\scripts\push-latest.ps1 -Tag v1.0.1
```
